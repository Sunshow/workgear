# Tasks: 修复服务停止时的孤儿进程清理问题

## 实施任务清单

### 模块：orchestrator（脚本管理）

#### 1. 修改 workgear.sh 脚本

- [ ] 在 `stop_service()` 函数的优雅退出阶段增加子进程清理（S）
  - 在 `kill -TERM "$pid"` 后添加 `pkill -TERM -P "$pid"`
  - 确保两个命令都使用 `2>/dev/null || true` 避免错误中断

- [ ] 在 `stop_service()` 函数的强制终止阶段增加子进程清理（S）
  - 在 `kill -9 "$pid"` 后添加 `pkill -9 -P "$pid"`
  - 确保两个命令都使用 `2>/dev/null || true` 避免错误中断

#### 2. 测试验证

- [ ] 在 Linux 环境下测试正常停止流程（M）
  - 启动所有服务
  - 执行 stop 命令
  - 验证所有主进程和子进程都已退出
  - 验证所有端口（3000/4000/50051）都已释放

- [ ] 在 Linux 环境下测试强制终止流程（M）
  - 启动服务后模拟进程无响应（kill -STOP）
  - 执行 stop 命令
  - 验证脚本能强制终止并清理子进程

- [ ] 在 macOS 环境下测试兼容性（M）
  - 执行上述所有测试场景
  - 验证 pkill -P 命令正常工作
  - 验证无 macOS 特有的错误

- [ ] 测试端口兜底清理机制（S）
  - 手动 kill 主进程但保留子进程
  - 执行 stop 命令
  - 验证端口兜底清理能清理残留进程

- [ ] 测试频繁重启场景（M）
  - 连续执行 10 次 restart 命令
  - 验证无孤儿进程累积
  - 验证无端口冲突
